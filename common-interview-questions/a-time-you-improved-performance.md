At my current company, we had a real-time messaging service that couldn't handle more than about 500 concurrent users —

 it kept falling over in production. I rebuilt it from scratch using FastAPI, WebSockets, and Redis. The biggest change was multiplexing — instead of each client opening multiple separate connections, I collapsed everything into a single connection per client. I also stripped out all the synchronous work, like database calls, from the message path entirely, so the service only does one thing: deliver messages between client and server, connecting directly to Redis and cutting down the round trips in between. On top of that, I fixed the timeout configuration across Cloudflare, Nginx, and Gunicorn, since those were silently killing long-lived connections. After the rebuild, it reliably handles 3,000-plus concurrent users on the same infrastructure we were already using — a 6x improvement without adding any new servers.
