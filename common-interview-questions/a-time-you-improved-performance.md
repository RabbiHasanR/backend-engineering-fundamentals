At my current company, we had a real-time messaging service that couldn't handle more than about 500 concurrent users — 

it kept falling over in production. I rebuilt it from scratch using WebSockets, FastAPI, and Redis, and designed it specifically to scale horizontally instead of just patching the existing code. After the rebuild, it reliably handles 3,000-plus concurrent users on the same infrastructure we were already using, so we got a 6x improvement without adding any new servers. The key was moving connection state out of the app process and into Redis, so we could run multiple instances behind a load balancer instead of being stuck with one server holding all the WebSocket connections in memory. Happy to go deeper into how that architecture works if useful.
