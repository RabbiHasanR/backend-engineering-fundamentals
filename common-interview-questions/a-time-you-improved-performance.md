At my current company — a sports-tech company building real-time live scoring and broadcasting for cricket, football, and other sports — our real-time messaging service is core to the product. During piloting, before the product went live, we found it couldn't handle more than about 500 concurrent users before falling over.

The company assigned me to solve this problem. I dug into why. There were three main problems: each client was opening multiple separate connections to the server instead of one, synchronous operations like database calls were sitting directly in the message-handling path, and the default connection timeouts in Cloudflare, Nginx, and Gunicorn were silently killing long-lived connections.

So I rebuilt the service from scratch using raw WebSockets. I fixed each problem directly: I introduced multiplexing so each client uses a single connection instead of several, I stripped out all synchronous work — including database calls — from the message path so the service does one thing only, deliver messages between client and server, and I reconfigured the timeout settings across Cloudflare, Nginx, and Gunicorn to properly support long-lived connections.

After the rebuild, the service reliably handles 5,000-plus concurrent users on the same infrastructure — a 6x improvement without adding any new servers.
